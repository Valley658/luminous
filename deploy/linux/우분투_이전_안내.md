# 루미너스 우분투 이전 안내

Windows 10 PC에서 돌던 루미너스를 Ubuntu Desktop(24.04 LTS 이상)으로 옮기는 순서입니다.
Windows 버전은 GitHub 기록(2026-10-02 이전 커밋)에 남아 있어요.

## 0. Windows에서 미리 챙길 것 (포맷 전에 USB/외장 디스크로)

**DB 백업이 제일 중요해요.** 포맷 전에 Windows 관리자 cmd 에서 (비밀번호를 물으면 .env 의 DB_PASSWORD):

```
"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysqldump.exe" -u root -p --single-transaction --routines --triggers --default-character-set=utf8mb4 pastellive_db --result-file=C:\Users\user\Desktop\pastellive_db.sql
```

| 무엇 | Windows 위치 | 우분투에서 넣을 곳 |
|---|---|---|
| DB 백업 | 위 명령으로 만든 `pastellive_db.sql` | 아무 곳 (복원할 때 경로 지정) |
| `luminous` 폴더 전체 | `C:\Users\user\Desktop\luminous` | `~/luminous` (아래 1번의 git clone 대신 통째로 복사해도 됨) |
| └ `.env`, `.secret_key` | `luminous\` | `~/luminous/` |
| └ 업로드·음악 | `luminous\static\uploads\`, `luminous\static\music\` | `~/luminous/static/` |
| └ JS 원본 | `luminous\frontend\` | `~/luminous/frontend/` |
| Cloudflare 인증서 | `C:\nginx\certs\pastellive_origin.pem`, `.key` | `/etc/nginx/certs/` |
| Cloudflare Tunnel 토큰 | Cloudflare Zero Trust 대시보드 → Networks → Tunnels | 설치 중 입력 |

`.env`, `.secret_key`, 업로드/음악, `frontend/`, 인증서, DB 백업은 GitHub에 올라가지 않으니 꼭 따로 옮기세요.

## 1. 우분투 설치 후

```bash
sudo apt update && sudo apt install -y git git-lfs
git lfs install
git clone https://github.com/Valley658/luminous.git ~/luminous
cd ~/luminous
# 위 표의 파일들(.env, .secret_key, uploads, music, frontend ...)을 복사
```

## 2. 전체 자동 설치

```bash
bash scripts/setup_luminous.sh
```

패키지(nginx, MySQL, ffmpeg, webp/avif 도구, python, node) 설치 → MySQL 계정/튜닝 → nginx → Meilisearch →
nsfw 파이썬 환경 → 서비스 등록(재부팅해도 자동 시작) → 잠자기 끄기 → 로그 정리 → Cloudflare Tunnel 순서로 진행돼요.
Cloudflare 인증서를 아직 안 넣었으면 임시 인증서로 먼저 띄우니, 넣은 뒤 `sudo deploy/linux/install_all.sh 4` 를 한 번 더 실행하세요.

## 3. DB 복원

```bash
sudo deploy/linux/install_all.sh 3 ~/옮긴파일/pastellive_db_20261002_xxxxxx.zip
```

`.zip`(Windows 백업), `.sql`, `.sql.gz` 모두 돼요. 끝나면 `scripts/서버재시작.sh`.

## 4. 확인

```bash
sudo deploy/linux/install_all.sh 12     # 서비스/포트/응답 진단
```

모두 정상이면 **Windows PC의 cloudflared를 끄거나 PC를 포맷**하세요. 같은 터널을 두 곳에서 돌리면 방문자가 두 서버로 나뉘어요.

## 자주 쓰는 명령 (예전 .bat 대응표)

| 예전 (Windows) | 지금 (우분투) |
|---|---|
| `scripts\빌드배포.bat` | `scripts/빌드배포.sh` (`--all` 이면 Rust/Zig 서비스도, `--rollback` 이면 되돌리기) |
| `scripts\서버재시작.bat` | `scripts/서버재시작.sh` |
| `scripts\JS빌드.bat` | `scripts/JS빌드.sh` |
| `START_SERVICE.bat` / `STOP_SERVICE.bat` | `scripts/start_service.sh` / `scripts/stop_service.sh` |
| `backup_db.ps1` | `scripts/backup_db.sh` (매일 04:00 자동) |
| `install_all.bat 11` (DB 복원) | `scripts/restore_db.sh <파일>` |
| `install_all.bat 7` (진단) | `sudo deploy/linux/install_all.sh 12` |
| `RDP_수정.bat` | `scripts/원격접속_설정.sh` (SSH + Tailscale + 우분투 원격 데스크톱) |
| `setup_luminous.ps1` / `전체자동설치.bat` | `scripts/setup_luminous.sh` |
| `_git_commit_push.bat` | `deploy/linux/_git_commit_push.sh "메시지"` |
| nginx 재적용 (`taskkill` + `schtasks`) | `sudo nginx -t && sudo systemctl reload nginx` (설정 다시 만들기: `install_all.sh 4`) |
| 작업 관리자에서 프로세스 확인 | `systemctl status pastellive` / `journalctl -u pastellive -f` |

## 서비스 구성

| systemd 서비스 | 하는 일 | 포트 | 로그 |
|---|---|---|---|
| `pastellive` | Go 웹서버 (watchdog 가 감시) | 8081 | `go-server/logs/service.log` |
| `pastellive-image` | 이미지 변환 (Rust) | 8091 | `services/c-image-service/logs/service.log` |
| `pastellive-nsfw` | 업로드 자동 검수 (Python) | 8095 | `services/nsfw-service/logs/service.log` |
| `pastellive-phash` | 재업로드 탐지 (Zig) | 8096 | `services/phash-service/logs/service.log` |
| `meilisearch` | 검색 | 7700 | `journalctl -u meilisearch` |
| `nginx` | 웹서버/캐시 | 80, 443 | `/var/log/nginx/` |
| `cloudflared` | Cloudflare Tunnel | (나가는 연결만) | `journalctl -u cloudflared` |
| `pastellive-backup.timer` | 매일 04:00 DB 백업 | | `logs/db_backup.log` |
| `pastellive-autodeploy.path` | bin 에 `*.new` 가 생기면 자동 교체 | | `logs/auto_deploy.log` |

Cloudflare Tunnel 은 PC에서 밖으로 나가는 연결만 쓰므로 **공유기 포트포워딩이 하나도 필요 없어요.**
KT 공유기에 있던 RDP(3389)·80·443 포트포워딩은 지우고, 원격 접속은 Tailscale 로 하세요.
